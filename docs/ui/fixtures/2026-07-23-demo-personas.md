## 4. 共用状态变体

两套 fixture 均应能在不改变人物基本事实的前提下切换：

| 变体 | 页面结果 |
| --- | --- |
| `happy_path` | 建档完成、双审核、双确认、计划到期生效 |
| `profile_incomplete` | 建档列出缺失字段，不进入计划准备 |
| `screening_review` | 停留人工复核时间线，不展示计划 |
| `diet_rejected` | 饮食被专业审核退回，用户端不可见该版本 |
| `training_rejected` | 训练被专业审核退回，用户端不可见该版本 |
| `user_rejected` | 用户拒绝任一部分，整版进入已退回待修改 |
| `risk_paused` | 疼痛或风险暂停关联任务并创建后台高优先级事件 |
| `insufficient_data` | 周调整保持核心目标，不收紧或加量 |
| `version_conflict` | 后台比较当前版本与最新版本，不自动覆盖 |
| `session_expired` | 保存本地草稿，重新登录后返回原任务 |
| `test_closed` | 计划与记录只读，仅保留允许的 P1 数据请求入口 |
