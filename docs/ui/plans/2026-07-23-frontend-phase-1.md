# 练伴 UI 第一阶段实施计划

> **执行要求：** 按测试驱动方式逐项实现；每个行为先写失败测试，再写最小实现。所有代码限定在 `frontend/`，文档限定在 `docs/ui/`。

**目标：** 建立由本地 mock 驱动的移动 H5 与 Web 后台前端基础，覆盖 32 个冻结页面入口、通用状态、两套演示人物和 P1 最小骨架。

**架构：** 正式 UI 工程位于研发部根 workspace 下的 `apps/web`，通过 `/h5/*` 与 `/web/*` 两组路由隔离移动端和后台页面状态；应用内 `src/shared` 只共享 token 和无业务状态组件，`src/mocks` 提供页面目录、两套 persona 与状态变体。应用仅消费 mock，不实现服务端权限或专业判断。

**技术栈：** TypeScript、React、React Router、Vite、Vitest、Testing Library、CSS custom properties。

---

## 文件结构

- `apps/web/package.json`：UI 应用命令与前端专用依赖声明。
- `apps/web/src/shared/`：token、布局、状态展示、演示警示。
- `apps/web/src/mocks/`：32 页面目录、persona 和演示状态。
- `apps/web/src/h5/`：移动端入口、路由和页面壳。
- `apps/web/src/admin/`：后台入口、路由和页面壳。
- `apps/web/src/**/*.spec.ts(x)`：页面目录、persona、路由和可访问性语义测试。
