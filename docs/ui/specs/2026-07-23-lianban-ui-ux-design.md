# 练伴封闭测试 MVP UI/UX 设计规格

版本：1.1
日期：2026-07-23
状态：待产品部最终复核
负责人：UI 部

## 1. 文档边界

本文定义移动 H5 与 Web 运营后台的信息架构、页面流程、交互状态、视觉系统、响应式规则和 UI 验收标准。本文不定义后端实现、数据库结构、鉴权算法、专业筛查规则或具体饮食训练处方。

产品范围与业务规则以 `docs/superpowers/specs/2026-07-23-closed-beta-mvp-product-decisions.md` 为准；技术接口以研发部维护的生效技术契约为准。发生冲突时，UI 部不得自行改变产品规则，应提交产品部决策；接口实现分歧由 UI 部与研发部直接协作解决。

首轮目标是完成高保真可点击原型。本文已达到 UI 开工评审所需细度，但不代表产品部已批准正式前端编码。正式前端编码必须在产品部最终复核、页面清单冻结和实施计划获批后开始。

## 2. 已确认范围

### 2.1 产品形态

- 中国大陆受邀健康成年健身新手使用的移动 H5；
- 面向运营人员、营养审核者和训练审核者的最小 Web 后台；
- 目标路线仅覆盖减脂与增肌；
- 首轮原型采用双端关键闭环，不制作非核心后台模块的完整交互。

### 2.2 首轮明确排除

- 自主注册、短信验证码和微信登录或绑定；
- AI 助手、AI 对话、AI 管理和 AI 生成内容；
- 支付、会员、社区、排行榜、挑战赛和商城；
- 设备接入、食物识别、动作识别和媒体上传；
- 医疗、诊断、疾病营养和运动康复；
- 非核心内容管理、员工管理和运营指标的完整后台交互。

### 2.3 原型数据

原型使用两套完整的真实感模拟数据：减脂新手与增肌新手。两套数据分别贯穿建档、计划、日常执行、周反馈和周调整。

饮食、热量、动作、组次和调整示例统一标记：

> 仅用于原型演示，未经专业审核

模拟内容不得进入真人测试计划。真人测试前必须替换为专业审核内容，且发布阻断不能只依赖前端提示。

原型提供减脂、增肌两个独立测试入口，并提供仅供演示人员使用的隐藏场景切换器。切换器不属于生产产品，不进入正式导航或生产接口。

两套模拟用户的完整产品级数据见 `docs/ui/fixtures/2026-07-23-demo-personas.md`。主规格只定义结构和页面消费规则，fixture 文档负责提供一致的跨页面演示事实。

### 2.4 P0 与 P1 边界

P0 是本轮高保真原型和后续首批前端实现的核心闭环：

- H5：受邀登录、首次改密、知情说明、筛查、建档、计划准备、待确认计划、双确认、今日任务、饮食记录、训练双录入、周反馈、周调整摘要和关键安全阻断；
- Web：员工登录、工作队列、用户复核、饮食审核、训练审核、发布待确认计划、周调整审核、风险与异常处理。

以下能力统一为 P1 最小入口，不计入 P0 闭环完成率：

- 消息中心：只提供未读提示、最小消息列表和任务深链，不制作消息偏好、批量管理或复杂会话；
- 数据导出/删除：只在“我的”提供入口、说明和提交结果，不在 P0 制作完整后台处理工作区；
- 测试账号操作：后台只保留创建、重置初始密码、解除锁定和停用入口，不建设完整账号管理模块。

P1 最小入口不得阻塞 P0 原型评审。若产品部改变其优先级，必须先更新冻结页面清单，UI 部不自行扩展交互深度。

## 3. 体验原则

1. 今日任务优先：优先回答用户今天做什么，而不是展示大量指标。
2. 安全先于连续性：风险、矛盾和系统失败时停止关联任务，不展示半成品。
3. 计划可解释：明确展示计划来源、版本、变化、原因和生效时间。
4. 轻量记录：先完成最小打卡，发生偏离或异常时再补充信息。
5. 不羞辱用户：使用偏离、未完成和等待调整等中性表达，不使用失败、惩罚或收紧作为情绪化反馈。
6. 状态透明：等待人工处理时说明当前阶段、预计时间、所需补充和下一步。
7. 历史不可覆盖：已发布和已生效版本只读，新变化通过新版本表达。

## 4. 移动 H5 信息架构

### 4.1 全局结构

底部主导航固定为：

1. 今日；
2. 计划；
3. 记录；
4. 我的。

消息中心从页面顶部通知入口进入。首轮不存在 AI 入口。

主导航外流程包括：

- 受邀账号登录；
- 首次修改初始密码；
- 知情说明和授权；
- 健康风险筛查；
- 分阶段建档；
- 初始计划准备时间线；
- 消息中心；
- 风险阻断、人工复核和系统异常页面。

### 4.2 今日

仅当前生效计划生成可执行任务。

页面顺序：

1. 日期、目标路线和消息入口；
2. 当日整体进度；
3. 饮食任务；
4. 训练或恢复任务；
5. 待完成反馈；
6. 非阻断提醒。

仅有待确认计划时，今日页显示确认提醒，不把计划内容列为可执行任务。初始计划被拒绝且无旧计划时显示等待修改；新版本被拒绝但旧计划仍有效时继续显示旧版任务，并展示非阻断修改提示。

### 4.3 计划

计划模块区分：

- 待确认计划；
- 饮食确认；
- 训练确认；
- 当前计划；
- 周调整摘要；
- 历史计划和版本说明。

待确认计划先展示目标周期、饮食摘要、训练摘要、安全说明、版本号和预计生效时间。饮食与训练分别确认。任一部分拒绝时必须选择原因，可选填补充说明；整份版本进入已退回待修改，不得部分生效。

### 4.4 记录

记录首页提供饮食、训练、恢复和周反馈入口。

饮食采用三态快速记录：按计划、部分偏离、明显偏离。选择偏离后才展开原因、文字说明和可选补充。

训练支持两种方式：

- 逐组实时记录：重量、次数、主观用力、完成状态和休息；
- 事后快速补录：动作级完成结果和关键组数据。

疼痛反馈必须立即停止相关动作的继续记录，引导进入安全处理路径，并保留其他不受影响任务的状态。

### 4.5 我的

包含个人档案、目标、授权与隐私、数据导出或删除、帮助、联系运营和退出登录。体重、围度保持选填；页面不得通过强提示制造必须填写的假象。

## 5. 移动 H5 核心流程

### 5.1 登录与首次改密

用户使用运营发放的受邀账号和初始密码登录。首次登录强制修改密码。页面覆盖密码错误、账号锁定、账号停用和会话过期。忘记密码只提供联系运营入口。

### 5.2 筛查与建档

筛查和建档采用短步骤分页，每一步保存进度。用户返回时从最近完成步骤继续。

结果分支：

- 通过：继续建档或进入计划准备；
- 需要人工复核：停止后续计划生成并显示时间线；
- 明确排除：说明产品边界并建议寻求适当专业帮助，不提供诊断结论。

资料缺失时列出缺少字段；资料矛盾时要求确认或进入人工复核。任何分支均不得展示半成品计划。

### 5.3 初始计划等待

状态时间线为：资料已提交、运营整理、专业审核、等待发布。页面展示预计完成时间、补充资料入口和联系运营入口，不展示临时通用计划。

### 5.4 发布、确认与生效

状态顺序：

```text
后台草案
-> 饮食审核中 + 训练审核中
-> 双审核通过
-> 发布为待确认计划
-> 用户分别确认饮食与训练
-> 双确认完成
-> 到生效时间后成为当前计划
```

用户看不到后台草案、审核中版本和审核意见。只完成一个部分的确认时，计划仍未生效。

### 5.5 周反馈与调整

周反馈收集执行情况、训练表现、恢复、睡眠、饥饿、压力、疼痛和选填身体趋势。

调整发布后先展示：

1. 改了什么；
2. 为什么改；
3. 哪些变量保持不变；
4. 何时生效；
5. 下周验证点。

用户随后可以进入完整计划和历史版本。数据不足时明确说明保持核心计划，不展示收紧热量、增加训练量或提高强度的暗示。

### 5.6 消息中心

消息类型包括计划发布、资料补充、审核结果、异常处理和人工回复。消息跳转到对应任务；进入目标页面后重新读取最新状态，不依赖消息生成时的旧快照。

## 6. Web 后台信息架构

### 6.1 全局结构

后台采用固定左侧导航、顶部任务工具栏和高密度内容区。

首轮深入实现：

- 工作台；
- 用户详情；
- 计划工作区；
- 风险与异常；
- 最小测试账号操作。

### 6.2 工作台

首屏四类待办：风险复核、计划审核、周调整审核、异常处理。

单条任务展示用户摘要、风险等级、状态、负责人、创建时间、截止时间和允许动作。默认排序优先级依次为风险、逾期、业务优先级和截止时间。

筛选支持任务类型、状态、优先级、负责人和时间。指标只提供轻量摘要，不作为首屏主体。

### 6.3 共享用户详情

运营人员与专业审核者查看同一用户上下文，包括档案、筛查结论、目标、执行趋势、恢复反馈、当前计划和版本历史。敏感字段按角色脱敏。

页面顶部固定展示当前阻断状态、待办任务、当前计划版本和允许动作。

### 6.4 计划工作区

桌面端采用三栏结构：

- 左栏：版本、饮食或训练章节、审核进度；
- 中栏：当前内容与关键数据；
- 右栏：审核意见、版本差异、风险提示和操作区。

运营人员可整理草案、回应退回意见并提交审核；营养审核者只处理饮食；训练审核者只处理训练。双审核通过后，运营人员才能发布给用户确认。

### 6.5 周调整审核

页面先展示本周事实、数据周期和可信度，再展示饮食与训练的前后差异、调整原因和保持不变的变量。数据不足时不提供收紧能量或增加训练负荷的操作。

### 6.6 风险与异常

任务状态为：待接单、处理中、等待用户补充、已解决。

页面提供安全文案、来源任务、负责人、截止时间、处理记录和结论。疼痛、恢复不良和筛查风险不提供诊断字段。所有状态变化写入审计记录。

### 6.7 最小账号操作

后台支持创建测试账号、重置初始密码、解除锁定和停用。完整账号管理不属于首轮核心闭环。

## 7. 角色与动作

### 7.1 运营人员

- 查看受邀用户和工作队列；
- 整理计划草案；
- 回应审核退回；
- 提交双审核；
- 在双审核通过后发布待确认计划；
- 处理非专业运营事项和账号操作。

### 7.2 营养审核者

- 查看与饮食审核相关的必要上下文；
- 批准或退回饮食部分；
- 填写结构化审核意见；
- 不审核训练或管理账号。

### 7.3 训练审核者

- 查看与训练审核相关的必要上下文；
- 批准或退回训练部分；
- 填写结构化审核意见；
- 不审核饮食或管理账号。

页面控件根据服务端返回的权限和允许动作显示。UI 不通过隐藏按钮替代后端权限控制。

## 8. 页面状态矩阵

每个核心页面统一覆盖：

| 状态 | UI 行为 |
| --- | --- |
| 加载中 | 使用与最终布局一致的骨架，不遮挡全部上下文 |
| 空数据 | 说明为空原因并提供当前下一步 |
| 正常 | 展示最新数据和允许动作 |
| 受限或阻断 | 展示原因、影响范围、处理人和恢复方式 |
| 提交中 | 防止重复提交并保留输入 |
| 提交成功 | 展示结果、版本和下一步 |
| 可重试错误 | 保留草稿并允许用户重试 |
| 不可重试错误 | 停止操作，展示联系入口和请求编号 |

关键异常：

- 会话过期：保存本地未提交草稿，重新登录后返回原任务；
- 字段错误：定位具体字段，不清空其他内容；
- 版本冲突：停止覆盖，刷新并比较用户版本与最新版本；
- 资料不足：列出需要补充项，不生成半成品；
- 风险复核：暂停关联任务，不给出诊断；
- 计划不可发布：后台展示具体阻断项；
- 系统计算失败：用户端不展示计划残片，后台创建高优先级异常；
- 网络中断：保留本地草稿，恢复后由用户确认再提交。

## 9. 数据与接口协作

1. 页面进入时读取身份、权限、业务状态和允许动作。
2. UI 根据稳定状态字段和允许动作渲染，不在前端复刻审核规则。
3. 编辑提交携带当前版本；成功后采用服务端返回的新版本。
4. 关键写操作使用幂等标识，避免重复打卡、审核或发布。
5. 列表项和训练组次使用稳定 ID 与明确顺序。
6. 消息深链只携带目标标识，目标页加载最新状态。
7. Mock 与真实 API 使用相同类型和状态语义。
8. 减脂与增肌分支由目标类型、计划版本和状态驱动，不按姓名或固定用户 ID 硬编码。

## 10. 视觉系统

### 10.1 场景化主题

今日和训练记录采用深色高对比主题；建档、饮食、周反馈、消息、我的和安全状态采用浅色主题。两类主题共享同一排版、间距、图标和组件语义。

荧光绿色只用于主操作、进行中状态和正向进度。风险使用红色，警告使用琥珀色，信息与人工处理中使用蓝色。状态同时使用文字与图标，不只依赖颜色。

### 10.2 核心颜色 token

| Token | 值 | 用途 |
| --- | --- | --- |
| `color.bg.light` | `#F7F9F7` | 浅色页面背景 |
| `color.surface.light` | `#FFFFFF` | 浅色面板、表格和输入表面 |
| `color.bg.dark` | `#111713` | 今日与训练深色背景 |
| `color.surface.dark` | `#1B241E` | 深色工具面板和训练组次行 |
| `color.text.primary` | `#172019` | 浅色背景主要文字 |
| `color.text.secondary` | `#59645D` | 浅色背景次要文字 |
| `color.text.onDark` | `#F5F8F5` | 深色背景主要文字 |
| `color.text.onDarkMuted` | `#B8C2BB` | 深色背景次要文字 |
| `color.brand.action` | `#B7F34A` | 主操作、进行中状态和正向进度 |
| `color.brand.actionText` | `#142000` | 荧光绿色按钮文字；禁止使用白字 |
| `color.info` | `#2563EB` | 人工处理中和信息状态 |
| `color.warning` | `#A85D00` | 警告和需要关注 |
| `color.risk` | `#C93636` | 风险和阻断 |
| `color.success` | `#267A45` | 完成和发布成功 |
| `color.border.light` | `#D9E0DB` | 浅色边界 |
| `color.border.dark` | `#3B4740` | 深色边界 |
| `color.focus` | `#155EEF` | 键盘焦点环 |

不得把状态色作为大面积页面背景。风险、警告和成功必须同时具有文字标签或图标。实际实现前需用自动化对比度检查验证所有前景/背景组合。

### 10.3 排版 token

- 字体栈：`system-ui, "Microsoft YaHei", "PingFang SC", sans-serif`；
- `font.size.12 = 12px`：仅辅助元数据；
- `font.size.14 = 14px`：紧凑后台正文和次要说明；
- `font.size.16 = 16px`：H5 主要正文、输入和按钮；
- `font.size.20 = 20px`：页面标题；
- `font.size.24 = 24px`：移动端关键数字和训练阶段标题；
- 行高依次为 `16 / 20 / 24 / 28 / 32px`；
- 字重只使用 `400 / 600 / 700`；
- 字号不随视口连续缩放，字间距固定为 0；
- 紧凑面板不使用营销式大字。

### 10.4 间距、圆角与层级 token

- 间距：`4 / 8 / 12 / 16 / 24 / 32 / 48px`；
- 移动页面左右边距：360px 为 16px，390–430px 为 20px；
- 后台内容区间距：16px，主要区块间距：24px；
- 圆角：控件 4px、面板 6px、独立卡片和弹层 8px；
- 阴影只用于浮层：`0 8px 24px rgba(18, 28, 21, 0.12)`；
- 层级：页面 0、固定导航 10、抽屉 30、模态 40、全局提示 50；
- 固定元素必须预留布局空间，禁止通过覆盖正文获得位置。

### 10.5 组件规则

- 卡片圆角不超过 8px；
- 不使用卡片嵌套或装饰性渐变球；
- 图标按钮使用统一图标库并提供名称提示；
- 二元设置使用开关或复选框；
- 模式选择使用分段控件；
- 数值使用输入、步进器或滑杆；
- 饮食使用三段状态选择；
- 训练组次使用稳定尺寸的行式记录控件；
- 安全阻断、等待和版本冲突使用独立状态页或明确横幅。

组件至少覆盖默认、悬停、焦点、按下、禁用、加载、成功和错误状态。按钮加载时保持原尺寸；表单错误不得导致后续内容无序跳动；训练组次行的动作区保持固定宽度。

### 10.6 动效

- 快速反馈 120ms，常规状态切换 180ms，抽屉与模态 240ms；
- 只使用透明度和位移，不用缩放制造按钮跳动；
- 计时器数字更新不得触发布局变化；
- `prefers-reduced-motion: reduce` 下关闭非必要位移和连续动画。

## 11. 响应式规则

### 11.1 移动 H5

重点验证 360px、390px 和 430px 宽度。

- 内容区使用稳定左右边距；
- 底部导航和训练操作区具有稳定高度；
- 窄屏下并排文字按钮可改为纵向排列；
- 最长中文标签不得溢出或遮挡相邻内容；
- 动态状态、计时和训练数据不得改变固定控件尺寸；
- 底部固定区考虑浏览器安全区域。

关键页面折叠规则：

| 页面 | 360px | 390–430px |
| --- | --- | --- |
| 今日 | 单列任务，进度与日期分两行 | 单列任务，进度与日期可同排 |
| 待确认计划 | 饮食/训练切换使用满宽分段控件，底部确认按钮纵向排列 | 两个确认状态可并排，主动作仍固定底部 |
| 饮食记录 | 三态选择纵向或等宽三列，最长文案允许两行 | 等宽三列 |
| 训练逐组 | 只保留组号、重量、次数、完成；RPE 进入展开区 | 组号、重量、次数、RPE、完成同排 |
| 周反馈 | 所有字段单列 | 短选项可两列，长文案单列 |
| 安全阻断 | 单列说明与唯一主动作 | 单列，不增加次要并排动作 |

移动端不设置小于 360px 的正式验收目标；低于该宽度时仍不得产生水平滚动或遮挡安全操作。

### 11.2 Web 后台

重点验证 1024px、1280px 和 1440px 宽度。

- 1280px 以上保持完整三栏工作区；
- 1024px 下允许收起次要侧栏或改用详情抽屉；
- 核心待办字段、风险状态和主要动作始终可见；
- 表格列按优先级隐藏，不允许整页横向失控；
- 高风险任务使用色条、图标和文字联合标识，不使用整行高饱和背景。

后台折叠规则：

| 宽度 | 工作台 | 用户详情 | 计划工作区 |
| --- | --- | --- | --- |
| `>= 1440px` | 完整列与常驻筛选 | 主内容 + 常驻侧栏 | 左中右三栏完整显示 |
| `1280–1439px` | 隐藏低优先级元数据，筛选仍常驻 | 次要趋势收进标签页 | 右栏缩窄，关键动作常驻 |
| `1024–1279px` | 筛选进入抽屉，保留风险/逾期/负责人/截止时间 | 次要信息进入抽屉 | 左栏可折叠，右栏改抽屉，中栏保持可编辑 |

低于 1024px 显示“不支持当前宽度处理后台任务”的明确提示，不提供可能造成误操作的压缩编辑界面。

## 12. 可访问性验收

以 WCAG 2.2 AA 为首轮目标：

- 普通文字对比度至少 4.5:1，大号文字和图形化控件至少 3:1；
- 所有可操作元素支持键盘，焦点顺序与视觉顺序一致；
- 焦点环至少 2px，不被固定导航、抽屉或容器裁剪；
- 触控目标至少 44 x 44px；
- 图标按钮具有可访问名称，装饰图标不进入可访问树；
- 表单字段具有持久标签、说明和程序化关联的错误信息；
- 字段提交失败时，焦点移动到错误摘要；摘要列出错误并可跳转到对应字段；
- 页面级阻断和会话过期使用 `role="alert"` 或等价即时播报；
- 普通保存成功和后台状态更新使用 `aria-live="polite"` 或等价非打断播报；
- 模态打开后焦点进入标题或首个有效控件，关闭后返回触发元素；
- 抽屉和模态必须支持 Escape 关闭，但安全确认流程不得因误按直接丢失输入；
- 颜色、位置和图标均不能成为唯一状态载体；
- 200% 浏览器缩放下核心任务仍可完成且不出现二维滚动。

验收组合至少包括：Chrome + 键盘、Edge + 键盘、Windows Narrator + Edge。自动化检查只能作为辅助，关键流程必须人工走查。

## 13. 原型组织

首轮采用“双端关键闭环”：

- H5 完整实现核心用户流程与关键安全异常；
- Web 后台完整实现复核、双审核、发布、周调整和异常处理；
- 非核心后台页面只保留信息架构，不制作完整交互。

高保真原型不是正式可商用产品。临时视觉比较稿不得作为功能完成证据。

## 15. 验收场景

必须覆盖：

1. 受邀账号登录、首次改密和会话恢复；
2. 筛查通过、人工复核和明确排除；
3. 资料缺失或矛盾阻断；
4. 计划准备时间线和补充资料；
5. 双审核后待确认计划可见但不生成今日任务；
6. 单侧确认后仍不生效；
7. 任一拒绝整版退回，旧计划存在时继续执行；
8. 三态饮食记录和偏离补充；
9. 训练逐组、事后补录和疼痛暂停；
10. 数据不足时保持核心计划；
11. 周调整摘要和历史版本；
12. 后台风险复核、双审核、发布、退回和版本冲突；
13. 未审核演示内容无法进入真人发布计划；
14. 加载、空、网络、无权限、系统失败和人工处理中状态。

## 16. 测试与交付标准

### 14.1 原型测试

- 记录任务完成率、理解错误、犹豫位置和放弃原因；
- 两套模拟用户均能独立走完核心流程；
- 所有模拟专业内容显示演示警示；
- 未完成专业审核前不用于真人健身指导。

### 14.2 前端验收

- H5 在 360、390、430px 无文字溢出、控件重叠或不可点击区域；
- 后台在 1024、1280、1440px 保持核心任务可用；
- 页面状态由接口字段驱动；
- Mock 与真实 API 的可观察行为一致；
- 关键组件、状态转换和双端闭环具备自动化测试；
- 键盘、焦点、语义标签和减少动态效果可用；
- 演示切换器不会进入生产构建。

## 17. 部门交付边界

UI 部维护：

- 本 UI/UX 规格；
- 高保真可点击原型；
- 视觉 token、组件规范和前端界面实现；
- 页面状态清单、mock fixtures 和前端测试。

研发部维护：

- 正式技术契约；
- 后端、数据库、鉴权、API、测试、部署和工程质量；
- 版本冲突、幂等、权限、审计和未审核内容发布阻断。

产品部维护：

- 产品范围、业务规则、优先级、验收口径和专业输入协调。

共享文档不得由多个部门同时编辑。跨部门变更必须先说明文件所有权和影响范围。
