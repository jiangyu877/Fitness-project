# 练伴 V1.0 P07 安全结构验收附件

版本：0.1
日期：2026-07-26
所有者：产品部
状态：方案 A 已获项目发起人选择，书面规格待最终复核

## 1. 文档效力

本文细化 `docs/product/lianban-v1.0-prd.md` 的 P07，以及 `docs/product/lianban-v1.0-identity-recovery-acceptance.md` 的 IR05-IR08。冲突时以 PRD 为准。

本文只定义授权、筛查结论和建档恢复的产品行为与验收结果，不定义 API 地址、数据库结构、令牌格式、专业筛查内容、隐私文案或建档字段。

## 2. 本批目标

在不引入任何未批准专业或隐私内容的前提下，完成以下真实结构闭环：

1. 有效 USER 会话按服务端唯一 `nextAction` 进入授权、等待筛查规则、人工复核、停止服务、建档或计划准备状态。
2. 授权页面只能读取服务端当前有效且已批准的版本化说明；加载失败或批准证据缺失时禁止接受。
3. 用户接受当前说明后，系统持久化授权记录并重新读取服务端会话状态，不在客户端推演下一步。
4. 用户端只读取筛查结论状态，不提交或模拟 `PASS`、`HUMAN_REVIEW`、`EXCLUDED`。
5. 仅当服务端确认筛查通过且存在已批准建档 schema 时，用户才能读取、恢复和保存建档草稿。
6. 筛查或建档未完成时不得创建计划、发布计划、返回任务候选或展示半成品专业内容。

## 3. 明确排除

本批不得实现或补造：

- 筛查题、风险阈值、排除条件、资料矛盾规则或固定安全文案；
- 饮食、训练、热量、动作、组次或周调整内容；
- 用户自行提交筛查结论、切换结论或绕过人工复核；
- 未经隐私复核的建档字段、默认值、必填规则或留存期限；
- 客户端根据缓存、路由、姓名、用户 ID 或本地表单推断业务状态；
- 真人账号、真人数据、G2、G3、staging 或生产放行。

自动化可以注入虚构且显式标记为测试用途的 provider，验证允许分支；测试注入不得改变默认环境的阻断结果，也不构成任何外部批准。

## 4. 状态与流转

本批复用既有 `nextAction`，不新增第二套状态机。

| 服务端 `nextAction` | 本批产品行为 | 禁止行为 |
| --- | --- | --- |
| `ACCEPT_CURRENT_CONSENT` | 读取当前批准说明及版本；用户明确同意后提交并重新恢复会话 | 无内容、版本过期或加载失败时提交 |
| `WAIT_FOR_SCREENING_RULES` | 展示安全等待状态和联系运营入口 | 展示问卷、阈值或继续按钮 |
| `COMPLETE_SCREENING` | 仅在专业 provider 已批准时进入其受控流程；本批默认仍阻断 | 用 UI fixture 或用户输入形成正式结论 |
| `WAIT_FOR_HUMAN_REVIEW` | 展示人工复核等待状态，不展示诊断 | 建档、计划或任务继续执行 |
| `STOP_SERVICE_FLOW` | 展示服务边界和联系运营入口，不展示诊断或处方 | 建档、计划或任务继续执行 |
| `COMPLETE_PROFILE` | 读取服务端批准的步骤顺序、字段 schema、当前版本和草稿 | 提交任意步骤名、任意字段或未批准数据 |
| `WAIT_FOR_PLAN` | 展示计划准备时间线 | 客户端自行创建计划或任务 |
| 未知、缺失或冲突 | 进入 `CONTACT_OPERATIONS` | 默认放行到下一步骤 |

只有服务端持久化的受信任结论可以决定状态：

```text
未接受当前授权 -> ACCEPT_CURRENT_CONSENT
已接受授权 + 专业规则不可用 -> WAIT_FOR_SCREENING_RULES
受信任结论 HUMAN_REVIEW -> WAIT_FOR_HUMAN_REVIEW
受信任结论 EXCLUDED -> STOP_SERVICE_FLOW
受信任结论 PASS + 建档未完成 + schema 已批准 -> COMPLETE_PROFILE
受信任结论 PASS + 建档完成 -> WAIT_FOR_PLAN
任一依赖未知、异常或审批证据不一致 -> CONTACT_OPERATIONS
```

## 5. 授权验收规则

1. 当前说明必须来自服务端批准 provider，并绑定唯一版本；UI 不得内置正式说明正文或版本。
2. 用户只能接受当前有效版本。旧版本、空版本或客户端伪造版本稳定拒绝且零授权写入。
3. 接受必须是明确用户动作，不预选、不因进入页面自动提交。
4. 写入必须具备可信 USER 主体、幂等、请求标识和成功审计；重复同一意图不得产生重复记录。
5. 成功后 UI 必须重新恢复会话并服从新的 `nextAction`。
6. 说明加载失败、provider 缺失或响应畸形时进入保守阻断，不提供错误重试；只有服务端明确允许 `RETRY` 时显示重试。

## 6. 筛查结论验收规则

1. USER 会话没有记录、修改或删除筛查结论的能力。
2. 专业规则未批准时，默认状态始终为 `WAIT_FOR_SCREENING_RULES`，且计划、任务和建档写入均为零。
3. `PASS`、`HUMAN_REVIEW`、`EXCLUDED` 必须带受信任来源和版本化依据；来源缺失、未知或审批不一致时 fail closed。
4. `HUMAN_REVIEW` 与 `EXCLUDED` 均不得返回诊断、专业建议、筛查原始规则或半成品计划。
5. 跨用户读取与不存在对象保持防枚举响应；拒绝行为使用可信会话主体审计。

## 7. 建档草稿验收规则

1. 建档入口必须同时满足：当前授权有效、筛查结论为 `PASS`、建档 schema 已批准。
2. 服务端返回有序步骤、当前步骤、整体版本、已完成步骤和当前草稿；UI 不硬编码流程是否完成。
3. 服务端只接受当前批准 schema 中存在的步骤和字段。未知步骤、未知字段、字段类型错误或 schema 版本不一致均稳定拒绝且零写入。
4. 每次保存携带服务端最新版本并支持同一用户意图幂等。版本冲突时 UI 保留本地输入、读取最新版本并提示用户处理，不静默覆盖。
5. USER 只能读取和保存本人草稿；员工、匿名和其他用户不得通过用户端入口读取草稿。
6. 请求指纹和审计不得持久化原始敏感字段值；字段值只进入经批准的业务存储。
7. 未批准 schema 时不得沿用现有任意 JSON 写入能力作为真实建档入口。

## 8. 错误与恢复

- 服务端返回结构化 `businessStatus`、`errorCode` 和 `recoverableActions`；UI 不解析自由文本决定流程。
- 未授权、越权、未知状态、畸形响应、provider 缺失和门禁不一致均 fail closed。
- 只有 `recoverableActions` 明确包含 `RETRY` 时显示重试；只有明确包含 `REFRESH` 时允许刷新版本。
- 所有成功写入后重新读取服务端事实；客户端不直接把本地成功状态当作最终业务状态。

## 9. 验收场景

| 编号 | 场景 | 必须结果 |
| --- | --- | --- |
| P07-01 | 当前说明 provider 缺失或异常 | 无说明正文、无接受按钮、零授权写入，进入保守阻断 |
| P07-02 | 加载当前批准说明 | 显示服务端版本化内容，不使用 UI 内置正式文案 |
| P07-03 | 接受旧版本或伪造版本 | 稳定冲突，零授权写入，要求刷新 |
| P07-04 | 同一授权意图重复提交 | 一条授权记录、一条成功审计、相同业务结果 |
| P07-05 | 授权成功 | 重新恢复会话；专业规则未批准时进入 `WAIT_FOR_SCREENING_RULES` |
| P07-06 | USER 尝试写筛查结论 | 稳定拒绝、零结论和计划写入 |
| P07-07 | 受信任结论为人工复核或排除 | 分别进入等待或停止状态，无诊断、建档、计划或任务 |
| P07-08 | 受信任结论通过但 schema 未批准 | 不开放任意 JSON 建档，进入保守阻断 |
| P07-09 | 建档草稿恢复 | 返回服务端步骤、版本、完成度和本人草稿 |
| P07-10 | 未知步骤、字段或 schema 版本 | 稳定拒绝且零写入 |
| P07-11 | 建档版本冲突 | UI 保留本地输入并按服务端动作刷新，不静默覆盖 |
| P07-12 | 建档完成 | 重新恢复会话并进入 `WAIT_FOR_PLAN`，不自动生成计划或任务 |
| P07-13 | 匿名、STAFF、跨用户访问 | 稳定拒绝；跨用户与不存在对象防枚举 |
| P07-14 | 任一真人门禁未关闭 | 真实业务路由零副作用拒绝，`readyForRealUsers=false` |

两套虚构用户必须使用同一状态与接口语义覆盖正常恢复、人工复核、排除、版本冲突和越权分支，不得按目标路线、姓名或固定用户 ID 绕过规则。

## 10. 部门边界

- 产品部：维护本文、范围、优先级、验收场景和超出权限的停止决策；不修改应用、API 或数据库。
- 研发部：自行定义技术接口和存储实现，完成服务端授权、provider 门禁、状态推导、幂等、审计和权限；不得定义专业规则或隐私字段。
- UI 部：实现服务端状态消费、批准内容展示、草稿恢复和错误恢复；不得内置正式筛查结论、建档字段或推演状态机。
- 专业、隐私和安全责任方：分别批准筛查规则、授权/建档字段及安全政策；产品部不得代签。

## 11. 精简验收流程

本批只执行以下验收轮次：

1. 研发部和 UI 部各自完成测试先行、范围自检和自动化验证。
2. 产品部执行一次联合验收，核对 P07-01 至 P07-14、两套虚构用户、全仓测试、类型检查、构建和工作树边界。
3. 只有变更触及认证授权、数据库迁移、隐私字段、专业结论来源或生产门禁时，增加一次对应专项独立复核；普通 UI 展示和既有契约消费不重复增加审查轮次。

本批完成不改变 P07 的总体 `施工中` 状态，直到批准的正式授权内容、建档 schema、专业筛查规则、真人环境和外部门禁取得证据。G2、G3 继续禁止。
