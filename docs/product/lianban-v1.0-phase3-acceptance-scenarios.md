# 练伴 V1.0 Phase 3 产品验收场景

版本：0.1
日期：2026-07-23
所有者：产品部
状态：施工验收附件

本文是 `docs/product/lianban-v1.0-prd.md` 的受控验收附件，仅定义 Phase 3 的可观察业务结果。它不定义 API 地址、数据库实现或专业规则；筛查题、风险阈值、安全文案、饮食/训练字段和调整边界仍以专业签字清单为准。

## 1. 用户端场景

| 编号 | 前置 | 操作 | 必须观察到的结果 | 禁止结果 |
| --- | --- | --- | --- | --- |
| C01 授权恢复 | 受邀用户已首次改密，授权尚未完成 | 打开授权页、离开后再次进入 | 显示当前说明版本、未完成步骤和明确同意/退出动作；同意记录可追溯 | 说明加载失败仍可提交同意；重复同意覆盖历史版本 |
| C02 筛查通过 | 已同意当前说明，筛查结果为允许继续 | 提交已批准筛查结构 | 进入建档；不展示诊断结论 | 客户端自行判定专业阈值；生成半成品计划 |
| C03 筛查人工复核 | 筛查命中待复核结构或资料矛盾 | 提交并查看结果 | 进入人工复核，展示补充资料/联系运营/等待结论；关联计划流程阻断 | 展示“安全/疾病诊断”；继续生成可执行任务 |
| C04 筛查明确排除 | 筛查命中已批准排除结构 | 提交并查看结果 | 停止计划流程，说明下一步和联系入口 | 提供替代处方、绕过阻断或自动恢复 |
| C05 分阶段建档 | 筛查允许继续 | 保存部分步骤后退出，再次进入 | 已保存草稿恢复；选填项不阻断；缺失/矛盾字段定位明确 | 丢失已保存输入；把选填项当必填 |
| C06 待确认不生成任务 | 计划处于待确认、超时、退回或等待生效 | 打开今日 | 显示准备/等待/处理状态；无可执行饮食或训练任务 | 使用待确认版本生成今日任务 |
| C07 当前计划记录 | 存在当前生效计划且任务未关闭 | 打开饮食/训练记录 | 饮食可选三态，偏离时出现原因字段；训练支持逐组记录与幂等补录 | 允许无计划记录；偏离直接被标记为失败或惩罚 |
| C08 风险暂停 | 训练记录或周反馈产生已批准风险结构 | 提交风险信息 | 仅暂停获批关联动作/任务；展示影响范围、下一步和联系入口 | 暂停全部无关任务；提供诊断；运营直接解除专业暂停 |
| C09 周反馈 | 反馈窗口开放 | 提交执行、表现、恢复和风险相关字段 | 记录周期、事实、缺失和提交结果；进入调整等待或人工处理 | 数据不足时自动收紧能量、加量或提强度 |
| C10 周调整查看 | 存在已发布但尚未生效的调整版本 | 查看调整说明 | 显示变化、原因、保持项、版本和生效时间；明确“确认不等于立即生效” | 把摘要当作当前计划；覆盖历史版本 |
| C11 数据请求 | 用户打开数据权利入口 | 提交导出或删除请求并查看状态 | 显示受理、核验、处理、完成/延迟状态；导出包有失效提示 | 无身份核验直接下载；静默延迟删除 |

## 2. Web 后台场景

| 编号 | 前置 | 操作 | 必须观察到的结果 | 禁止结果 |
| --- | --- | --- | --- | --- |
| C12 共享用户详情 | 员工拥有对应用户权限 | 从队列打开用户详情 | 按角色展示最小必要字段，风险置顶，显示当前计划/历史/待办上下文 | 只靠前端隐藏敏感字段；跨用户越权 |
| C13 风险接单 | 存在风险事件 | 运营或对应审核者打开事件 | 可接单、记录处理、等待补充；权限动作按角色过滤 | 运营写入专业恢复结论；详情给出诊断 |
| C14 双专业审核 | 饮食和训练部分分别待审核 | 对应专业角色审核 | 每部分独立批准/退回；审核人、角色、版本和原因可追溯；自审禁止 | 一个角色替代另一专业；已发布原地修改 |
| C15 调整复核 | 周反馈形成调整草案 | 查看事实、可信度、差异和保持项 | 数据不足显示保持/解决执行阻力路径；业务变化进入完整新版本流程 | 跳过双审核、发布或用户双确认 |
| C16 数据请求处理 | 存在用户导出/删除请求 | 运营接单并记录核验和结果 | 用户端状态同步；安全事件只冻结最小相关记录且有具名例外 | 扩大冻结范围；无审计覆盖处理结果 |

## 3. 跨端和安全验收

- `FAT_LOSS` 与 `MUSCLE_GAIN` 必须使用同一状态语义和组件/API 结构，仅由目标类型与版本数据驱动差异。
- 演示 fixture 始终显示“仅用于原型演示，未经专业审核”，并保持 `demoOnly=true`、`reviewStatus=DEMO_UNREVIEWED`、`publishable=false`；任何发布入口都只能显示阻断结果。
- 所有关键写操作必须可重复提交而不产生重复业务副作用；版本冲突必须返回最新状态和可恢复动作。
- 授权、筛查、风险、审核、发布、确认、超时、导出、删除和账号操作必须携带操作者/角色、对象、版本、时间、结果和请求标识审计信息。
- 测试视口：H5 360/390/430px；Web 1024/1280/1440px。关键状态不得依赖颜色单独表达，键盘焦点和错误摘要必须可观察。

## 4. 外部门禁

以下未签字前只能验收结构、阻断和 mock，不得用于真人计划或真人封测：

- 风险筛查题、排除/复核条件与资料矛盾规则；
- 红旗、疼痛、恢复不良的固定文案、暂停范围、恢复条件和响应时限；
- 饮食/训练字段、单位、内容来源、替换和调整规则；
- 最低数据充分性、周调整变化边界和运营升级 SLA；
- MFA、密码、会话、锁定、重置核验、部署和隐私留存实施细则。
