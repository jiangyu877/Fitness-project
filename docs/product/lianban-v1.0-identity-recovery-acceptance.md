# 练伴 V1.0 身份恢复与路由门禁验收

版本：0.1
日期：2026-07-23
所有者：产品部
状态：冻结的下一批验收语义

本文细化 `docs/product/lianban-v1.0-prd.md` 中 P05-P07、P18 的可观察业务结果，不定义 API 地址、数据库、令牌格式、密码算法或部署实现。冲突时以 PRD 为准。

## 1. 首次登录与改密

1. 受邀用户提交有效初始凭据后，只能获得用于首次改密的受限身份上下文，不能直接获得授权、建档、计划或其他用户能力。
2. 首次改密必须绑定服务端已验证的受限上下文；客户端不得通过提交账号 ID、角色或布尔值指定改密对象。
3. 改密成功后，服务端建立完整 USER 会话，并返回下一步；用户不需要再次输入新密码。
4. 受限上下文必须短时、单次使用；错误初始密码、锁定、停用、过期和重复使用均 fail closed，并按身份安全契约审计。
5. 忘记密码和无法完成首次改密只提供联系运营路径；V1.0 不提供短信、微信或公开自助找回。

## 2. 会话恢复

有效 USER 会话恢复时，服务端必须返回当前账号类型、会话到期时间、当前业务状态和唯一 `nextAction`。UI 不得依据本地缓存、姓名、用户 ID、拥有的全部角色或历史页面自行推断下一步。

稳定 `nextAction` 语义：

| `nextAction` | 产品含义 | UI 目标 |
| --- | --- | --- |
| `CHANGE_INITIAL_PASSWORD` | 仅完成受限身份验证 | 首次改密 |
| `ACCEPT_CURRENT_CONSENT` | 尚未接受当前有效知情说明 | 知情说明与授权 |
| `WAIT_FOR_SCREENING_RULES` | 真人筛查规则或文案未批准 | 安全等待页，不展示问卷 |
| `COMPLETE_SCREENING` | 已批准筛查结构可填写 | 健康风险筛查 |
| `WAIT_FOR_HUMAN_REVIEW` | 筛查或资料需要人工复核 | 人工复核时间线 |
| `STOP_SERVICE_FLOW` | 已形成明确排除结论 | 停止计划流程，不提供诊断或处方 |
| `COMPLETE_PROFILE` | 筛查允许继续且档案未完成 | 最近未完成建档步骤 |
| `WAIT_FOR_PLAN` | 建档完成，计划尚未发布 | 计划准备时间线 |
| `VIEW_PENDING_PLAN` | 存在唯一待确认计划 | 待确认计划 |
| `VIEW_TODAY` | 存在当前生效计划 | 今日 |
| `CONTACT_OPERATIONS` | 账号、会话或业务状态需人工处理 | 联系运营/阻断页 |

未知、缺失或互相冲突的状态必须进入更保守的 `CONTACT_OPERATIONS`，不得默认继续流程。

## 3. 授权、筛查与建档恢复

- 授权页必须读取当前有效说明版本和用户是否已接受该版本；说明加载失败时禁止提交同意。
- 筛查题、排除条件、人工复核条件、资料矛盾规则和安全文案未具名批准前，真人流程只能返回 `WAIT_FOR_SCREENING_RULES`，不得把 UI 占位字段提交为正式筛查。
- 用户端不得调用或模拟专业人员的筛查结论写入能力。`PASS`、`HUMAN_REVIEW`、`EXCLUDED` 只能来自受信任的专业规则或具备资格的人工复核。
- 档案恢复必须返回步骤顺序、最近未完成步骤、每步版本和已保存草稿；客户端提交必须携带服务端最新版本并在冲突时保留本地输入。
- `HUMAN_REVIEW`、`EXCLUDED`、资料缺失、资料矛盾或系统失败时不得生成半成品计划。

## 4. 环境与路由门禁

| 路由类别 | 本地/自动化 | Staging | 真人环境未就绪 | 真人环境已就绪 |
| --- | --- | --- | --- | --- |
| 健康检查、就绪状态 | 允许，不含敏感数据 | 允许 | 允许 | 允许 |
| 虚构 demo fixture | 仅显式 demo 模式允许 | 仅脱敏/虚构数据允许 | 禁止 | 禁止 |
| 员工登录、应急停用、门禁处理 | 测试策略显式注入后允许 | 对应安全策略批准后允许 | 对应安全策略批准后允许 | 允许 |
| 用户首次登录、改密、会话恢复 | 仅虚构测试账号允许 | 仅获批准的测试账号允许 | 禁止 | 允许 |
| 用户授权、筛查、建档、计划读写 | 仅虚构数据与批准测试策略允许 | 仅获批准的演练数据允许 | 禁止 | 按角色与业务状态允许 |
| 真人账号导入、真人数据录入、真人计划发布 | 禁止 | G3 全部门禁关闭前禁止 | 禁止 | 按权限允许 |

研发可选择环境标识、route metadata 和 guard 结构，但必须保证 readiness 与路由放行使用同一门禁快照。缺少 provider、未知路由、未知阻断码、证据版本不一致或依赖异常一律拒绝。测试中注入“已批准”只验证代码分支，不构成真实审批。

## 5. 下一批验收场景

| 编号 | 场景 | 必须结果 |
| --- | --- | --- |
| IR01 | 有效初始凭据登录 | 只返回受限改密上下文和 `CHANGE_INITIAL_PASSWORD` |
| IR02 | 受限上下文完成改密 | 建立完整 USER 会话，下一步为 `ACCEPT_CURRENT_CONSENT` |
| IR03 | 恢复有效会话 | 返回服务端当前状态、到期时间和唯一 `nextAction` |
| IR04 | 会话过期或账号停用 | 不恢复业务数据，返回稳定拒绝和 `CONTACT_OPERATIONS`/登录路径 |
| IR05 | 当前说明未接受 | 加载版本化说明；加载失败不可同意；成功后重新读取下一步 |
| IR06 | 专业筛查规则未批准 | 返回 `WAIT_FOR_SCREENING_RULES`，无问卷提交和计划生成 |
| IR07 | 专业结论为人工复核或排除 | 分别进入等待或停止流程，不显示诊断、处方或计划 |
| IR08 | 档案步骤恢复与冲突 | 从最近未完成步骤恢复；409 保留输入并获取最新版本 |
| IR09 | 真人环境任一门禁未关闭 | 用户身份/onboarding/计划业务路由零副作用拒绝 |
| IR10 | 未分类新真人路由 | 自动化门禁测试失败，不能默认放行 |

## 6. 外部门禁

本文不批准认证参数、MFA、HMAC 密钥管理、筛查规则、专业内容、隐私文本、部署环境或真人测试。对应责任方证据未完成时，系统只能实现结构、虚构测试和 fail-closed 行为。
