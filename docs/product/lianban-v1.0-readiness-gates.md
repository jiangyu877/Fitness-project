# 练伴 V1.0 真人服务就绪门禁

版本：0.1
日期：2026-07-23
所有者：产品部
状态：冻结的产品语义，审批证据待补

本文细化 `docs/product/lianban-v1.0-prd.md` 第 7、8、10、12、13 节的真人服务门禁，不新增专业、安全或隐私参数。技术路由和字段结构由研发附件维护。

## 1. 就绪定义

`readyForRealUsers=true` 只表示系统已具备启动真人封闭测试的全部 G3 证据，不等同于正式商用或公开发布。

只有下列条件同时成立时才允许返回 `true`：

- 当前环境未启用 demo/mock 身份或演示内容；
- 本表全部阻断码均已由对应责任方以版本化证据关闭；
- 当前发布物与审批证据对应同一不可变版本；
- 最近一次权限、安全、数据权利、备份恢复和风险升级验收仍在有效期内。

开发和 staging 可以在阻断码存在时运行，但必须返回 `readyForRealUsers=false`。任何单一审批都不能清除其他门禁。

## 2. 稳定阻断语义

| 阻断码 | 产品含义 | 关闭责任方 | 最低关闭证据 |
| --- | --- | --- | --- |
| `DEMO_MODE_ACTIVE` | 当前环境或内容仍是演示模式 | 研发负责人 + 产品负责人 | demo 路由停用；发布版本不引用 demo 内容；环境证据 |
| `PROFESSIONAL_RULES_UNAPPROVED` | 筛查、风险、饮食、训练或周调整任一专业输入未批准真人用途 | 对应专业审核方 | 专业签字清单四领域明确批准真人封测，版本与复审日期齐全 |
| `AUTH_SECURITY_POLICY_UNAPPROVED` | MFA、密码、会话、锁定、重置核验或入口隔离政策未批准/未验证 | 安全负责人 + 产品负责人 | 认证安全决策记录；权限矩阵与高风险测试通过 |
| `PRIVACY_REVIEW_UNAPPROVED` | 字段级收集、留存、匿名化、冻结例外或告知文本未完成合规复核 | 隐私负责人 + 产品负责人 | 字段级留存映射、告知版本与合规复核记录 |
| `DATA_RIGHTS_DRILL_INCOMPLETE` | 授权撤回、导出、删除/匿名化尚未完成有证据演练 | 隐私负责人 + 运营负责人 | 三类演练结果、审计记录和异常处理证据 |
| `BACKUP_RESTORE_DRILL_INCOMPLETE` | 备份恢复、迁移失败或 worker 重放尚未验证 | 研发负责人 | 恢复报告、数据校验和无重复副作用证据 |
| `OPERATIONS_READINESS_INCOMPLETE` | 值班、风险升级、超时通知或人员培训未就绪 | 运营负责人 + 专业审核方 | 值班表、SLA、升级流程和演练记录 |
| `DEPLOYMENT_SECURITY_UNAPPROVED` | HTTPS、域名/备案、秘密管理、监控、告警或回滚未批准 | 研发负责人 + 安全负责人 | 环境清单、安全检查、监控告警与回滚演练 |

客户端必须按稳定代码选择状态，不解析自由文本。新增、拆分或废弃阻断码需先更新本附件和产品验收台账。

## 3. 环境行为

| 环境 | 允许内容 | 就绪结果 |
| --- | --- | --- |
| 本地开发 | 虚构 fixture、结构状态和安全阻断 | 始终 `false`，至少含 `DEMO_MODE_ACTIVE` 及尚未批准项 |
| 自动化测试 | 虚构 fixture；单测可显式构造批准策略验证允许分支 | 测试结果不能作为真实审批；默认配置仍为 `false` |
| staging | 虚构或获明确授权的脱敏数据、双端联调和演练 | 在全部 G3 证据关闭前为 `false` |
| 真人封测环境 | 仅批准版本、受邀真实参与者和最小必要数据 | 只有全部门禁关闭才可为 `true` |

## 4. UI 验收

- 就绪阻断不得只用颜色表达；应展示当前不可用、影响范围和下一步，不展示诊断或技术堆栈。
- 同时存在多个阻断时必须完整保留，不得只显示第一项后把整体状态误判为可用。
- demo 安全字段不匹配、未知阻断码或接口失败时，客户端必须进入更保守的安全阻断/本地 fallback。
- 真人发布、真实账号导入和真实数据录入入口在 `readyForRealUsers=false` 时均不可执行。

## 5. 审计要求

每个门禁的开启、关闭、重新开启和证据版本变化必须记录责任人、当前角色、时间、证据版本、发布物版本、结果和请求标识。产品部只协调和验收完整性，不代替责任方批准。
