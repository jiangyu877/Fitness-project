## Frozen Port Mapping

The existing application-wide protected-route middleware remains route-first and unchanged. The frozen order is: global route snapshot -> controller session/role -> strict request/schema -> repository -> endpoint mapper. The existing test-only endpoint adapter derives all controller-local authority server-side; a production endpoint/database adapter and real-user success remain uncreated and unauthorized. The client supplies only the existing strict command body and correlation/idempotency headers. After the global route allows the request, the test-only adapter must:

1. authenticate the bearer as a trusted USER before task disclosure;
2. obtain a pinned strict test-only schema and infer each entry `valueType` from its selected field;
3. hash or otherwise derive the repository-approved session credential representation without exposing the raw bearer to persistence;
4. pass `taskId`, request ID, idempotency key, schema snapshot, and typed command to the port;
5. map the port result to exactly `businessStatus`, `recordVersion`, `schemaVersion`, `nextAction`, and `recoverableActions`;
6. consume the port's `ok: true | false` outcome union and map every internal failure without throwing arbitrary objects or returning persistence details;
7. keep `HMAC_KEY_UNAVAILABLE` internal and fail closed as the existing public route/readiness error.
