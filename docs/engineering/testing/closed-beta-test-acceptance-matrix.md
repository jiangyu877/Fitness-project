# 练伴封闭测试 MVP 测试与验收矩阵

状态：产品 v1.1 指标已映射，待三方复核
日期：2026-07-23
所有者：研发部

## 1. 测试层级

| 层级 | 目标 | 开工前证据 |
| --- | --- | --- |
| 静态检查 | 类型、格式、依赖和秘密扫描 | CI 阻断级规则通过 |
| 单元测试 | 纯状态转换、权限判定、值对象和错误映射 | 允许/禁止分支均有用例 |
| 数据库测试 | 约束、事务、并发、迁移和 outbox | 临时 PostgreSQL 实例通过 |
| API 契约测试 | OpenAPI schema、错误、幂等和权限 | mock 与真实 API 共用样例 |
| 组件/状态测试 | UI 状态、字段错误、权限动作和恢复 | H5/Web 自动化组件测试 |
| 集成测试 | 跨模块事务和后台任务 | 发布、暂停、生效和消息闭环 |
| E2E | 两套目标分支和后台审核闭环 | 支持视口矩阵的浏览器测试 |
| 安全测试 | 认证、授权、CSRF、越权、限流和敏感数据 | 高风险问题为零 |
| 恢复测试 | 备份恢复、迁移失败和 worker 重放 | 演练记录和校验报告 |

## 2. 核心验收矩阵

| 编号 | 场景 | 必须验证 | 依赖 |
| --- | --- | --- | --- |
| A01 | 受邀账号登录/首次改密 | 初始密码不可继续使用；会话域隔离；错误码稳定 | 密码/会话政策 |
| A02 | 锁定、停用、重置 | 停用立即失效；重置过程审计；不得枚举账号 | 锁定阈值、核验流程 |
| A03 | 知情说明/分步建档 | 同意版本追加；步骤恢复；选填字段不阻断 | 同意文本和必填矩阵 |
| A04 | 筛查通过/复核/排除 | 不返回诊断；阻断准确；无半成品计划 | 专业筛查规则 |
| A05 | 资料缺失/矛盾 | 稳定原因代码、补充动作和人工待办 | 冲突规则 |
| A06 | 双专业审核 | 五角色隔离；对应部分禁止自审；退回后生成新版本；审核历史不可改 | 专业资格清单 |
| A07 | 发布待确认 | 未双审/含 demo 内容均阻断；发布幂等 | 内容审核规则 |
| A08 | 饮食/训练双确认 | 单侧不生效；任一拒绝整版退回；每用户仅一份待确认；超时后拒绝确认 | 无 |
| A09 | 到期生效 | 截止为生效日前一日 20:00 CST；同日期最多一个活动版本；重复 worker 不重复生效 | 无 |
| A10 | 今日任务 | 只来源于活动计划；待确认版本不生成任务 | 任务生成规则 |
| A11 | 饮食/训练记录 | 三态条件字段；逐组/补录幂等；稳定排序 | 字段/单位定义 |
| A12 | 疼痛与恢复风险 | 事务内创建风险事件并暂停获批范围；仅对应资格审核者给出恢复结论，运营不能改结论 | 风险阈值、暂停范围、SLA |
| A13 | 周反馈/调整 | 数据周期、事实、可信度、差异、保持变量完整；业务变化创建完整新版本并重走全流程 | 充分性和调整专业规则 |
| A14 | 工作队列 | 风险/逾期/优先级/截止时间稳定排序；权限过滤 | SLA、角色权限 |
| A15 | 消息深链 | 只带目标；打开后重读状态；越权/失效安全处理 | 消息类型清单 |
| A16 | 数据导出/删除 | 字段范围、身份核验、审计、备份例外符合矩阵 | 留存和删除矩阵 |
| A17 | 版本冲突 | 返回最新版本和冲突字段；禁止静默覆盖 | 无 |
| A18 | 系统计算失败 | 用户无计划残片；后台异常与 requestId 可追踪 | 异常等级/SLA |
| A19 | 计划空档 | 旧计划按原结束时间终止；无替代版本时无今日任务且返回显式空档 | 无 |
| A20 | 数据生命周期 | 30 天处理可识别数据、12 个月记录、7 天导出和 30 天备份任务可验证 | 隐私/合规复核 |

每个核心页面必须覆盖 `LOADING`、`EMPTY`、`READY`、`BLOCKED`、`SUBMITTING`、`SUCCEEDED`、`RETRYABLE_ERROR`、`TERMINAL_ERROR`。

## 3. 目标路线与视口

- `FAT_LOSS` 和 `MUSCLE_GAIN` 使用同一 schema、不同 fixture，分别完整通过 A03-A15。
- H5：360、390、430px；Web：1024、1280、1440px。
- 两条路线不得按用户 ID 或姓名硬编码。
- 视口变化不得改变 API 字段、权限和业务状态。

## 4. 并发与幂等

必须覆盖：

- 同一审核重复提交相同 `Idempotency-Key`；
- 两名员工使用相同 `expectedVersion` 并发编辑；
- 发布请求超时后重试；
- 生效 worker 重复消费 outbox；
- 训练组次离线重试与乱序到达；
- 风险暂停与任务完成同时发生；
- 新版本生效与旧版本任务生成跨日竞争。
- 两次发布竞争创建第二份待确认版本；
- 确认请求与 20:00 CST 超时 worker 同时发生。

成功标准是单一可解释结果、无重复业务副作用、完整审计和稳定错误码。

## 5. 权限与安全矩阵

对每个员工 API 至少测试：允许角色、其他登录角色、无会话、跨用户对象、停用账号和过期会话。字段脱敏必须在服务端验证。

安全用例包括密码暴力尝试、会话固定、CSRF、IDOR、批量赋值、注入、日志敏感信息、demo 发布绕过、审计修改和导出链接复用。

员工 MFA 是否启用、会话时长、锁定阈值和导出身份核验等待批准；测试占位只记录依赖，不预设值。

## 6. 迁移与恢复矩阵

| 场景 | 通过标准 |
| --- | --- |
| 空库建库 | 全部迁移一次成功且 schema 校验通过 |
| 上一版本升级 | 应用前后版本在 expand 阶段均可运行 |
| 中途失败 | 事务回滚或明确前向修复，无半迁移状态 |
| 大表变更 | 有锁评估、批处理和超时保护 |
| 备份恢复 | 恢复后活动计划、审计和 outbox 校验通过 |
| worker 重放 | 不重复发消息、不重复生效、不重复创建待办 |

## 7. Mock 与真实 API 一致性

OpenAPI 3.1 schema、状态样例和错误样例作为共同输入。CI 对 mock 和真实 API 运行同一契约测试。Mock 不实现业务判断，只选择已定义场景；真实 API 不返回契约外状态。

## 8. 发布门槛

进入真人封闭测试前至少满足：

- 产品与 UI 规格冻结；
- 专业输入签字并替换 demo 内容；
- P0 自动化测试通过，关键 E2E 无阻断失败；
- 高危安全问题为零，权限矩阵全部通过；
- 数据删除/匿名化和备份恢复完成演练；
- 监控、告警、值班和回滚操作手册可用；
- H5/Web 视口矩阵完成验收。

覆盖率百分比不是单独发布依据；状态机、权限、风险、发布和恢复关键分支必须 100% 映射到用例。

## 9. 四周封闭测试成功标准

测试数据同时报告人数和比例，并验证：

1. 至少 6 人开始、至少 5 人完成四周；
2. 至少 4 名完成者达到有效执行：至少三周提交周反馈，且每周至少四天提交最小饮食或训练记录；
3. 总体周反馈提交率不低于 75%；
4. 周调整理解确认率不低于 80%，下一周实际采纳率不低于 60%；
5. 至少 4 名完成者认可饮食训练联动价值；至少 3 名在明确价格后愿意继续付费；
6. 每用户每周人工服务时间中位数不超过 45 分钟；
7. 无未关闭严重安全事件，且筛查、审核和风险暂停不可被绕过；
8. 授权撤回、导出、删除/匿名化至少各完成一次有证据的演练。

安全门槛不满足时，无论其他指标如何都不得进入下一阶段。P05/P06 专业签字仍是开展真人测试的前置条件。
