状态：研发跟踪基线
日期：2026-07-23
所有者：研发部

## 1. 门槛定义

- `G0 技术准备`：只允许 ADR、ERD、契约方案、测试和部署设计。
- `G1 核心编码`：允许建立应用、数据库和 P0 接口。
- `G2 双端联调`：允许 UI 使用真实 API 完成闭环。
- `G3 真人封闭测试`：允许录入真实参与者数据和发布专业计划。

当前处于 `G0`。产品基线 v1.1 已冻结 P01-P04 的业务口径，但仍待产品、UI、研发三方开工复核和技术映射；复核通过前不得创建应用源码、依赖或可执行迁移。

## 4. G1 核心编码检查表

只有 P01-P04 完成三方复核和技术映射，且 P05/P06 至少冻结技术字段骨架后，才能申请进入 G1。开工评审还需确认：

- ADR 技术栈和模块边界获批；
- 数据库与迁移工具选择获批；
- OpenAPI 所有权和版本策略获批；
- 认证安全参数由产品/安全确认；
- 仓库主分支、远程、CI 和秘密管理可用；
- 环境启动脚本是可执行初始化命令，不指向 `.git` 目录；
- 不存在未归属的共享文件或并行编辑冲突。

## 5. G2 联调检查表

- UI 规格冻结；
- P0 OpenAPI schema 与错误样例冻结；
- 两套完整 fixture 通过 schema 校验；
- mock 与真实 API 通过同一契约测试；
- 权限、状态、时间、单位和分页行为一致；
- staging 可访问且只含虚构/授权脱敏数据；
- requestId、日志和错误追踪可用于联调。

## 6. G3 真人测试检查表

- 专业材料完成具名签字，demo 内容全部替换或被服务端阻断；
- 数据留存、删除/匿名化和备份例外已实现并演练；
- 高风险安全问题为零，角色与字段权限测试通过；
- 备份恢复、迁移回滚、异常值班和告警完成演练；
- 用户同意文本、数据权利入口和运营联系渠道可用；
- 产品、专业审核、UI、研发和隐私负责人共同签字。

## 7. 已冻结的技术映射输入

1. 确认截止为计划生效日前一天 20:00（中国标准时间），且运营至少提前 24 小时发布。
2. 同一用户同一时刻最多一份待确认版本；超时版本不可继续确认。
3. 旧计划只执行到原结束时间，之后进入空档，不自动延长、不使用待确认计划生成任务。
4. 周调整只要改变业务含义，就创建完整新计划版本并重新完成双审核、发布、双确认和到期生效。
5. 首轮五角色为运营、营养审核、训练审核、系统管理员、审计查看者；允许多角色，但禁止审核自己编制的对应部分。
6. 风险恢复结论仅由具备对应专业资格的审核者给出；运营只能执行通知和流程操作。
7. 可识别用户/健康/执行数据在测试结束后 30 天内删除或匿名化；授权记录和去标识审计保留 12 个月；导出包 7 天；备份滚动最长 30 天。
