# 练伴封闭测试 MVP 开工依赖清单

状态：研发跟踪基线
日期：2026-07-23
所有者：研发部

## 1. 门槛定义

- `G0 技术准备`：只允许 ADR、ERD、契约方案、测试和部署设计。
- `G1 核心编码`：允许建立应用、数据库和 P0 接口。
- `G2 双端联调`：允许 UI 使用真实 API 完成闭环。
- `G3 真人封闭测试`：允许录入真实参与者数据和发布专业计划。

当前处于 `G0`，不得创建应用源码、依赖或可执行迁移。

## 4. G1 核心编码检查表

只有 P01-P04 已批准，且 P05/P06 至少冻结技术字段骨架后，才能申请进入 G1。开工评审还需确认：

- ADR 技术栈和模块边界获批；
- 数据库与迁移工具选择获批；
- OpenAPI 所有权和版本策略获批；
- 认证安全参数由产品/安全确认；
- 仓库主分支、远程、CI 和秘密管理可用；
- 环境启动脚本是可执行初始化命令，不指向 `.git` 目录；
- 不存在未归属的共享文件或并行编辑冲突。

## 5. G2 联调检查表

- UI 规格冻结；
- P0 OpenAPI schema 与错误样例冻结；
- 两套完整 fixture 通过 schema 校验；
- mock 与真实 API 通过同一契约测试；
- 权限、状态、时间、单位和分页行为一致；
- staging 可访问且只含虚构/授权脱敏数据；
- requestId、日志和错误追踪可用于联调。

## 6. G3 真人测试检查表

- 专业材料完成具名签字，demo 内容全部替换或被服务端阻断；
- 数据留存、删除/匿名化和备份例外已实现并演练；
- 高风险安全问题为零，角色与字段权限测试通过；
- 备份恢复、迁移回滚、异常值班和告警完成演练；
- 用户同意文本、数据权利入口和运营联系渠道可用；
- 产品、专业审核、UI、研发和隐私负责人共同签字。

## 7. 当前仍需产品决定的问题

1. 当前三份产品/设计文档是否共同构成 v2.0，正式批准人和冻结提交是什么？
2. 周调整是否完全复用计划的双审核、双确认和到期生效流程？
3. 用户确认晚于生效时间、多待确认版本、旧计划到期时如何处理？
4. 同一员工能否兼任运营、营养和训练角色，双审核是否必须由不同自然人完成？
5. 风险暂停影响哪些任务，谁能恢复，处理和升级时限是什么？
6. 数据、审计、日志、导出和备份各自保留多久，删除请求有哪些例外？
7. 员工是否强制 MFA，会话时长、密码和锁定策略由谁批准？
8. 部署在中国大陆还是其他区域，预算、备案、域名和可用性目标是什么？
