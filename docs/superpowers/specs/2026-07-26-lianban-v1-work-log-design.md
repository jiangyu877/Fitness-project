# 练伴 V1.0 工作登记表设计

日期：2026-07-26  
状态：已获用户确认，待书面规格复核  
适用版本：练伴 V1.0

## 1. 目标

在 `docs/product/lianban-v1.0-work-log.md` 建立一份可持续追加的 Markdown 工作登记表，用于记录 V1.0 施工期间的重要问题、分析、修改、验收证据与后续动作。

登记表不替代以下权威资料：

- `docs/product/lianban-v1.0-prd.md`：产品范围和业务规则的唯一权威来源；
- `docs/product/lianban-v1.0-acceptance-ledger.md`：P01-P21 产品要求的总体验收状态；
- UI、研发、专业、安全和隐私附件：各责任范围内的详细规格与批准证据。

## 2. 文档结构

登记表使用以下七列：

| 字段 | 用途 |
| --- | --- |
| 时间 | 记录发生或完成核验的时间，使用中国标准时间 |
| 问题/目标 | 简明描述本次要解决的问题或达成的目标，并标明责任范围 |
| 分析了什么 | 记录查阅的规格、代码、测试、运行结果或其他证据 |
| 易错点 | 记录容易误判、遗漏或破坏既有规则的关键风险 |
| 修改了什么 | 记录实际变更的文件、模块或规则；未修改时明确写明 |
| 验收 | 记录已经执行的测试、检查及结果；未执行的项目不得写成通过 |
| 状态/后续 | 使用统一状态并写明下一步、责任方或阻断条件 |

## 3. 状态规范

仅使用以下状态：

- `分析中`：正在收集证据，尚未形成可执行结论；
- `施工中`：已经开始修改，但尚未完成与风险相称的验收；
- `待验收`：修改已完成，等待产品、UI、研发或外部责任方复核；
- `已完成`：目标范围内已有匹配的修改和验收证据；
- `已阻断`：缺少必须由指定责任方提供的决定、批准或外部条件。

每条记录在“问题/目标”中使用 `[产品]`、`[UI]`、`[研发]` 或 `[联合]` 标明主要责任范围。专业、安全、隐私、运营和部署门禁不得由登记表自行判定关闭。

## 4. 首批记录范围

首批记录依据当前仓库可验证证据填写，覆盖：

1. V1.0 产品基线及 32 页范围冻结；
2. 减脂与增肌两套演示人物及演示内容隔离；
3. 受邀身份、首次改密和身份恢复；
4. 计划生命周期、持久化和双确认规则；
5. 角色权限、专业资格和自审禁止；
6. 真人服务就绪门禁与当前阻断项；
7. 当前仍未完成的 P0/P1、视口、无障碍及真人封测验收。

每条记录必须区分已提交证据、当前未提交施工内容和尚未实施事项。当前工作树中的未提交改动只能标记为施工中或待验收，不能仅凭文件存在标记为已完成。

## 5. 维护规则

- 新问题或独立验收结果新增一行，不覆盖历史事实；
- 同一问题继续推进时可以新增后续行，并引用前一条时间或目标；
- 修改产品状态时，同时更新权威验收台账，登记表只保留过程记录；
- 验收列优先写测试名称、运行结论和关键计数，避免使用“已检查”等模糊表述；
- 表格内容保持摘要级，详细证据通过仓库相对路径引用；
- 不记录密码、令牌、个人敏感数据或真实参与者信息；
- 时间不确定时使用核验时间，并在内容中说明它不是原始发生时间。

## 6. 验收标准

登记表完成时应满足：

- 文件位于 `docs/product/lianban-v1.0-work-log.md`；
- 标题、用途、状态说明和七列表格完整；
- 首批记录均能追溯到当前仓库证据；
- 没有把未提交、未运行或外部门禁写成已完成；
- 与 PRD 和产品验收台账不存在状态或范围冲突；
- Markdown 表格可正常解析，仓库内部链接有效。
