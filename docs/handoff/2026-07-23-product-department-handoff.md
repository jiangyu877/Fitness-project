## 1. 项目目标

为通过筛查的受邀健康成年人提供四周减脂或增肌封闭测试服务，形态为移动 H5 + 最小 Web 运营后台。V1.0 验证计划执行、人工周调整、饮食训练联动价值和付费意愿，不提供医疗、康复或 AI 能力。

## 7. 已知问题

- PRD 页首仍写“待开工评审批准”，与用户已授权施工的事实不一致；只能修正文档状态，不能改业务规则。
- 产品验收台账落后于最新身份安全实现，更新前必须先取得独立质量审查结论。
- 筛查、安全、饮食、训练和周调整专业内容尚未具名批准；隐私、认证参数、MFA、运维和部署证据也未闭环。
- 当前系统只适合本地演示和结构验证，不可解释为真人封测或生产就绪。

## 8. 下一步要做什么

1. 恢复研发部身份安全独立质量审查；只在审查和全量验证通过后更新 P05/P06。
2. 产品部最终复核 UI v1.2 与两套 fixture，确认它们未改变 PRD。
3. 校准 PRD 页首状态和验收台账，使文档状态与已提交证据一致。
4. 与安全负责人批准认证参数/MFA方案，与专业、隐私、运维责任人逐项收集门禁证据。
5. 按 P0 闭环持续验收：身份建档 -> 计划 -> 每日记录 -> 周反馈/调整 -> 风险处理。

## 9. 不能改动/需要注意的约束

- 产品部不得修改 `apps/**`、`packages/**` 或擅自定义 API/数据库实现。
- PRD 是唯一权威来源；UI 和工程附件只能细化，不能改变业务规则。
- 不得自行编造筛查题、阈值、热量、动作、组次、安全文案或周调整规则。
- 演示内容必须标注“仅用于原型演示，未经专业审核”，且不得进入真人已发布计划。
- V1.0 不得加入 AI、公开注册、短信/微信登录、支付、社交、媒体上传、设备接入、医疗或康复能力。
- 产品部只能协调门禁完整性，不能代替专业、安全、隐私、运维或部署责任人批准。
